# Claude Fable 5.1 与 Mythos 5.1 发布：性能升级、护栏更准、成本更低！

我们正式推出 **Claude Fable 5.1** 和 **Claude Mythos 5.1**。它们是目前全球最先进的编码与知识工作模型，其研究能力也初步展现了 AI 模型如何为科学进步做出贡献。

Claude Fable 5.1 和 Claude Mythos 5.1 是同一个模型，只是安全护栏的等级不同。Fable 5.1 已全面开放，而 Mythos 5.1 仅通过我们的可信访问计划（trusted access programs）提供，其护栏专门设计用于支持网络安全的工作。

## 1 客户反馈

采取重要举措：

### 1.1 价格

在按 token 计费的所有场景中，Fable 5.1 的典型工作负载成本预计比 Fable 5 低约 25%。这因为我们降低了缓存读取（cache reads，即模型读取已处理并存储过的输入）的价格。对于高度智能体（agentic）的工作，节省幅度往往更大——最高可达约 45%。

### 1.2 数据保留

全新的企业前沿安全护栏系统（Enterprise Frontier Safeguards，EFS）在提供完整隐私保障（与零数据保留策略相同）的同时，依然是防止对抗性滥用的最先进水平。EFS 的工作原理是将数据存储在完全由客户控制的云基础设施上，而非 Anthropic 的系统上。它将于今秋开始分阶段向企业客户开放。在 EFS 可用之前，符合条件的客户将能够以零数据保留方式使用 Fable 5.1。

### 1.3 安全护栏

我们改进了护栏以减少误报（即系统标记了无害内容的情况）。在网络安全领域，最新护栏相比之前的版本减少了 60% 的误报。部分原因是 Fable 5.1 现在可用于发现软件漏洞——但不能用于开发漏洞利用（exploit）。

## 2 新的性能前沿

Claude Fable 5.1 为编码、知识工作和长时间运行的任务设定了新标准。Fable 5.1 的性能远超其前代 Fable 5。而在设置低（Low）或中（Medium）努力等级时，Fable 5.1 以更低成本达到了与 Fable 5 相当甚至更好的结果。（注意：Fable 5.1 在 Claude Code 中默认使用高努力等级，在 Claude Cowork 和 Claude.ai 上默认为中等。）

Fable 5.1 避免了导致工作质量下降的捷径，它足够聪明，能够修复软件问题的根本原因。如投资公司 Millennium 的测试中，Fable 5.1 找到了其内部系统中一个罕见崩溃的原因——在数年的尝试中，该工程师团队（或其他任何模型）都无法解释这一崩溃。

## 4 安全、安保与对齐

过去两年，AI 模型的智能体能力变得强大得多。但正如我们[所记录的](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals)，更大的自主性也带来了新的风险。安全、安保和对齐工作必须与 AI 能力的进步保持同步。昨天，我们[发布了一份报告](https://www.anthropic.com/news/improving-alignment-security-efforts)，描述了我们如何改进自身对齐和安保工作。

在发布 Claude Fable 5.1 和 Claude Mythos 5.1 之前，我们（在某些情况下还有外部研究人员）对模型进行了广泛的、涵盖多个领域的风险测试。我们在[系统卡（System Card）](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)中完整描述了这些工作，以下是简要总结。

**网络风险。** 我们运行了一系列评估来衡量 Claude Mythos 5.1 的网络能力（关闭网络安全护栏）。总体而言，该模型展示了我们所发布的任何模型中最强的网络能力，尽管在我们的[前沿合规框架（Frontier Compliance Framework）](https://www.anthropic.com/news/compliance-framework-SB53)中仍属于较低风险类别。我们还对 Fable 5.1 的网络安全护栏进行了广泛压力测试：除了我们自己的动态评估以验证其稳健性之外，我们还委托了两个外部机构进行测试，并搭配了 [Gray Swan](https://www.grayswan.ai/) 的自动化测试。与 Fable 5 和 Opus 5 一样，我们未发现在这些护栏上存在[严重级别越狱（critical-severity jailbreak）](https://www.anthropic.com/news/fable-safeguards-jailbreak-framework)的证据。

**智能体安全。** 我们评估了 Claude Mythos 5.1 对恶意请求和提示注入（prompt injection，即隐藏在 AI 模型处理内容中的对抗性指令）的反应。它对恶意智能体编码和计算机使用请求的拒绝率与 Mythos 5、Sonnet 5 和 Opus 5 相当，并且在外部[提示注入基准测试](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)上是我们迄今最稳健的模型。

**对齐。** 我们通过静态和交互式行为评估、使用[自然语言自编码器](https://www.anthropic.com/research/natural-language-autoencoders)分析其内部思维、与不对齐相关的能力评估、对训练数据的审查，以及对我们内部试点使用的分析，测试了模型的行为。我们还收到了外部测试的报告。

我们的自动化行为审计发现，Claude Mythos 5.1 在大多数指标上比其前代 Mythos 5 有更好的对齐。当被分配一个本质上不可能完成的任务时，该模型尝试访问测试环境外部资源的可能性显著低于 Mythos 5。它还比 Mythos 5 更不可能使用动机性推理（motivated reasoning）来为其行为辩护（例如，推理当前情境是一个模拟或评估），并且更不可能在追求用户目标时忽略明确约束。从我们对训练数据的审查来看，Mythos 5.1 尝试奖励作弊（reward hacking）和成功作弊的总体比率都低于 Mythos 5。

尽管我们的对齐评估总体上显示出改进，但我们的测试发现，该模型仍有时能绕过审批和自动模式分类器（我们在[系统卡](https://www.anthropic.com/claude-fable-5-1-mythos-5-1-system-card)中详细讨论）。我们的对齐评估覆盖范围也存在局限性。目前，我们的自动化行为审计对超长上下文工作和多智能体设置的可见性较低。我们对不可能任务的覆盖（这类任务可能引发更异常和不对齐的行为）也比我们希望的要少，尽管我们最近在这一领域取得了改进，并正在努力继续推进。

我们还改进了护栏，使我们的模型在不牺牲安全性的前提下更加有用。以下是这些变化的说明。

**企业自动护栏。** [企业前沿安全护栏（Enterprise Frontier Safeguards，EFS）](https://www.anthropic.com/news/enterprise-frontier-safeguards)允许我们在检测并响应模型滥用的同时，向企业客户提供零数据保留协议的隐私保障。使用 EFS，客户将其数据存储在自己的云基础设施上，而非 Anthropic 的系统上；任何人工审查默认由客户自己完成，而非 Anthropic。我们在金融服务、医疗、制造、电信、法律、零售和公共部门等 100 多位客户以及我们的云合作伙伴 AWS、Google Cloud 和 Microsoft Azure 的密切协作下开发了 EFS。

EFS 将在 Claude Code、Claude Enterprise、Claude Platform、Amazon Bedrock、Claude Platform on AWS、Google Agent Platform 和 Microsoft Foundry 上得到支持。它将从今秋开始分阶段推出。如前所述，符合 EFS 条件的客户在 EFS 就绪之前，可以以零数据保留方式使用 Fable 5.1（以及 Fable 5）。你可以在[这里](https://www.anthropic.com/news/enterprise-frontier-safeguards)阅读更多关于 EFS 的信息；要申请访问权限，请填写[此表格](https://claude.com/form/enterprise-frontier-safeguards)。

**更精确的网络安全护栏。** 过去几个月，我们在使 Fable 5.1 的护栏更加精确方面取得了进展：确保它们更不可能标记无害内容（例如关于医疗问题的查询，或网络安全防御者使用模型使其系统更安全），同时确保它们对真正的威胁仍提供稳健保护。

对于 Fable 5.1，我们更新了网络安全护栏以提高精确度。我们现在还允许 Fable 5.1 用于识别软件漏洞——即进行那种能改善软件安全性的防御性工作。由于这些变化，Claude Code 用户可以预期，与 Fable 5 上的先前护栏相比，我们的网络安全护栏每次会话的介入次数平均减少约 60%。但我们的护栏仍会将几类双重用途网络安全任务（可能有有益_或_有害应用的任务）引导至我们的 Opus 模型。这包括渗透测试、漏洞利用生成和基于二进制的漏洞扫描。

**反蒸馏机制。** 蒸馏（distillation）是一种用于提取高级模型能力的方法。它常被大规模工业化使用，借助数千个虚假账号。蒸馏是一种安全风险，因为被蒸馏的能力随后可能在缺乏适当护栏的情况下被发布。Fable 5.1 配备了增强的机制，使蒸馏攻击更难实施。例如，新的 API 账号（从今日起创建的）不再能在多轮对话中手动编辑 Claude 的先前上下文，同时保留 Claude 先前思维的记录。这封堵了一种常见的、已被公开记录的蒸馏技术，该技术允许蒸馏者非法提取 Claude 的思维。我们将逐步推出这一变化，以最大限度减少影响：现有账号目前不受此变化影响，但未来模型发布时将适用于所有用户。少数客户的自定义集成将受到影响。我们的[帮助中心文章](https://support.claude.com/en/articles/16761192)详细说明了这一变化以及开发者可以做出的调整。

## 6 欧盟 AI 法案合规

2026 年 7 月，Anthropic（与[另外 190 位签署方](https://digital-strategy.ec.europa.eu/en/news/strong-backing-code-practice-transparency-ai-generated-content)，包括其他几家主要 AI 模型提供商）签署了欧盟 AI 法案关于 AI 生成内容透明度的行为准则（Code of Practice）。

这要求我们为 2026 年 8 月 2 日之后发布的模型输出添加水印——一种数值方法，用于判断一段文本被 Claude 参与书写的可能性。正如我们[最近解释的](https://www.anthropic.com/news/claude-text-watermark)，这个水印对没有检测 API 的人来说是不可见的。它对 Claude 输出的质量或内容没有实际影响，也不包含任何关于用户、其组织或其与 Claude 对话的信息。

该法案还要求我们提供一种方式，让用户判断文本是否可能包含水印。因此，我们正在以私有预览（private preview）形式推出检测 API。它目前根据欧盟法律要求，可供符合条件的组织使用（例如监管机构、执法机构、媒体、事实核查者、独立研究人员、教育组织和欧盟公民社会团体）。它也可供有类似义务需要验证水印以合规的企业使用。我们计划随时间推移扩大检测 API 的访问范围。你可以[在此](https://forms.gle/9tGA33hPJJwtHsMk9)注册访问意向。

## 7 成本与可用性

Claude Fable 5.1 今天已在全平台可用，包括 Amazon Web Services、Google Cloud 和 Microsoft Azure。开发者可以在 Claude API 上使用 `claude-fable-5-1` 开始使用。

如前所述，我们降低了 Fable 5.1 缓存读取的价格（模型复用其已处理过的上下文），适用于按 token 计费的所有场景，例如在我们的 API 上。缓存读取现在的价格降低了 75%，为每百万 token 0.25 美元。
