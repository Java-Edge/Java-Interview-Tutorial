# “思考模式”是怎么来的？看看这些推理模型的技术思路

## 0 前言

距离 OpenAI 发布 o1 已经快两年了，这款模型让基于 LLM 的推理模型这一概念深入人心。大约四个月后，DeepSeek-R1 紧随其后，并公开了使用可验证奖励强化学习（RLVR）训练此类推理模型的详细方案。

上周，OpenAI 发布了 GPT-5.6 模型家族。它包含三个尺寸，每个尺寸大致都有五到六个推理力度（reasoning-effort）档位。

## 1 推理模型的简要定义

几乎任何机器学习或 AI 技术或子领域时，有一条经验：通常不应"按字面意思"理解技术术语。如，机器学习和 AI 中的（人工）神经网络并不像人脑这样的生物神经网络那样真正运作。

谈到"推理模型"时，也不应期望这些模型真的像人类一样推理。AI 和 LLM 研究的语境中，"推理模型"指一种输出中间推理轨迹（intermediate reasoning trace）的模型——类似于一种逐步拆解问题或任务的中间响应。

看例：传统 LLM 的回答（左）与推理模型的回答（右）示意图

## 2 推理模型的训练扩展与推理扩展概览

本质上，提升（推理）任务性能有两种方式：
- 训练扩展（training scaling）
- 推理扩展（inference scaling）

训练扩展与推理扩展是提升 LLM 和推理模型解题能力的两种方式。图表基于 [Learning to reason with LLMs](https://openai.com/index/learning-to-reason-with-llms/)

### 2.1 训练推理模型

DeepSeek-R1提出使用可验证奖励强化学习（RLVR）训练 LLM，将其转变为推理模型。RLVR 是一种为可验证数据领域提供奖励信号（`0=错误`，`1=正确`）的技术。这里的可验证数据领域包括数学（可以使用 SymPy 或 WolframAlpha 等符号数学检查器来验证结果）和代码（可以使用编译器或单元测试，或 LeetCode 等集成平台来检查正确性）。

![img](https://substackcdn.com/image/fetch/$s_!tGXl!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F874e07b2-d461-4ae5-bbda-f8204ae16420_1999x945.png)

RLVR 训练中准确率奖励与格式奖励的示意图。

推理轨迹本身并未用于训练或更新模型。尽管他们尝试过将这种中间响应信息用于训练，但 DeepSeek-R1 论文报告称这对模型训练没有帮助，因此最终没有采用。（是否以及如何通过过程奖励模型（process reward model）将中间推理轨迹纳入训练信号，目前仍是一个活跃的研究方向。）

![img](https://substackcdn.com/image/fetch/$s_!df0g!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fa8ffc0b7-2ba0-462e-98a6-734226250175_1999x925.png)

RLVR 期间中间推理轨迹被忽略；只有最终答案和响应格式决定奖励。

如下图，仅靠输出奖励进行训练就足以让模型学会如何推理问题——也就是说，它会学会写出中间解释、回溯并自我修正。模型意识到自己犯错并进行自我修正的这些时刻，被称为"顿悟"（Aha）时刻。

一个"顿悟"时刻的示例——推理模型在中间推理中发现错误，并在给出最终答案之前予以纠正。


虽然 DeepSeek-R1 无疑是更受关注的论文，也是引发人们对可验证奖励强化学习和推理模型开发热情的论文，但还有另一篇论文——[Kimi K1.5](https://arxiv.org/abs/2501.12599)——在 arXiv 上于同一天（2025 年 1 月 22 日）发布。此外，RLVR 这个术语在两个月前的 [Tülu 3: Pushing Frontiers in Open Language Model Post-Training](https://arxiv.org/abs/2411.15124) 中就已经被提出。
DeepSeek-R1 最终更受欢迎的原因之一是，它证明了纯强化学习（RL）即可实现推理行为。

虽然 R1-Zero 更像是一个概念验证模型，但完整的 DeepSeek-R1 推理模型训练流程通常是多阶段的，也稍微复杂一些。

如今大多数 LLM 实际上都是推理模型，也就是说它们都以类似 DeepSeek-R1 的方式，使用某种形式的 RLVR 训练。

### 2.3 推理扩展简述

除了通过训练改善推理行为，另一提升模型性能的杠杆是推理时计算扩展（inference compute scaling）。即在模型训练完成后、使用阶段投入更多计算，以获得更好的答案。

这本身就是一个完整的话题，阅读《The State of LLM Reasoning Model Inference》获取更详细的梳理：
![The State of Reinforcement Learning for LLM Reasoning](https://substackcdn.com/image/fetch/$s_!pmzH!,w_140,h_140,c_fill,f_auto,q_auto:good,fl_progressive:steep,g_auto/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F9c02ecf0-cb1d-4f62-a160-6d07636b99fd_1600x1384.png)
[Sebastian Raschka, PhD](https://substack.com/profile/27393275-sebastian-raschka-phd)

最核心的背景信息：

- 使用 RLVR 训练模型本身就隐含了一种推理扩展形式，因为推理模型在推理时通常比传统 LLM 输出更多 token，这意味着我们在推理时投入了更多计算
- 可通过推理力度档位进一步调整输出长度，稍后详述
- 还有许多额外的推理扩展技术。其中一种流行的方法是自一致性（self-consistency），通常实现为多数投票的形式——多次查询模型，然后通过多数投票选出最终答案

![img](https://substackcdn.com/image/fetch/$s_!lgDp!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F5ce7222d-19fb-4578-a9ec-aa60f21d5587_1999x1185.png)自一致性（一种流行的推理扩展技术）示例。

这种方法既适用于传统 LLM，也适用于推理模型。此外，它可以按需使用，并且可以与推理训练叠加。一个很好的例子是 DeepSeekMath-V2，研究人员在一个（专门针对数学的)推理模型之上应用了极端推理扩展，在高难度的数学奥林匹克类型问题上取得了最先进的性能。

![](https://substackcdn.com/image/fetch/$s_!gHJX!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F8103d00f-ddd8-457d-b115-545311d7c40e_1999x1338.png)

两种推理扩展方式（自一致性和自我精炼）结合使用以提升数学性能。图改编自 [DeepSeekMath-V2: Towards Self-Verifiable Mathematical Reasoning](https://arxiv.org/abs/2511.22570)

## 3 Think 标记

你可能在前面的"顿悟时刻"图中看到过 `<think></think>` 标记：

![img](https://substackcdn.com/image/fetch/$s_!IcTg!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fec1eeb79-6e2d-4236-a9e4-fdd6b61517e5_1999x1236.png)推理模型中常见的格式标记。



这些 `<think>` 和 `</think>` 标签对于推理能力而言只是装饰性。它们不会让模型具备推理能力，也不是取得良好推理性能所必需。不使用这些分隔符训练同一个模型，很可能也能达到相近的基准测试性能。

这些 `<think>` 标签或标记的主要作用是标记推理轨迹的起止位置，以便训练流程或用户界面能将其与最终答案分离，并可选地对用户隐藏。（ChatGPT 或 Codex 等界面通常就是这么做的。）

字面字符串 `<think>` 和 `</think>` 本身也没有什么特别之处。换一对分隔符同样可以达到目的。

其实现方式通常是在 RLVR 阶段添加一个格式奖励。也就是说，不仅仅根据答案正确性给予奖励，还会对使用 `<think>` 标记提供额外奖励，从而鼓励模型使用这些标记。如 DeepSeek-R1 中，总奖励计算为

```properties
R_total = R_accuracy + R_format
```

其中格式奖励是一个简单的基于规则的检查，鼓励模型将推理内容放在：

```java
<think>
reasoning trace
</think>
```

## 4 推理模式的开关

第一代推理模型是专用推理模型：有一个 DeepSeek-V3 基座模型，还有一个独立的 DeepSeek-R1 推理模型。

无论提示词是什么，R1 通常都会输出非常冗长响应，消耗大量 token，即使是简单提示词。它没内置关闭推理模式的选项。

![img](https://substackcdn.com/image/fetch/$s_!HzqR!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F2f980538-0730-4518-a685-d1574cd78b7a_1999x1271.png)

推理模型即使面对最简单的提示词也非常冗长。

后来模型如Qwen3，尝试混合方法——同一个模型可按需表现为常规的指令微调模型，也可表现为推理模型。

> 有些模型开发者称之为"思考模式"（thinking mode），另一些则称之为"推理模式"（reasoning mode）。两个术语指同一种行为。

Qwen3中通过分词器用 `enable_thinking=True` 或 `enable_thinking=False` 来处理。底层设置 `enable_thinking=False` 本质是在助手响应的开头添加一个空的 `<think></think>` 段，以关闭 Qwen3 的推理（"思考"）模式。

![img](https://substackcdn.com/image/fetch/$s_!5647!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fbbaa28da-a17e-462b-88d3-4c28ac863ef6_1999x1224.png)Qwen3 0.6B 推理模型在 `thinking=False` 和 `thinking=True` 下的响应。（左侧界面中隐藏了空的 `<think></think>` 标签，因为它们是修改后的输入提示词的一部分，而非生成的答案。）

训练时咋能让模型在推理时支持如上图所示的开关切换？如 [Qwen3 技术报告](https://arxiv.org/abs/2505.09388) 解释，这种开关行为主要通过监督微调（SFT）引入，然后在其最大旗舰模型的通用 RL 阶段得到强化。

如在通过长思维链 SFT 和推理 RL 训练出初始推理模型后，他们增加一个"思考模式融合"（Thinking Mode Fusion）阶段。在这个额外的 SFT 阶段，模型同时看到思考和非思考示例：

- `/think: <think>{reasoning}</think>{answer}`
- `/no_think: <think></think>{answer}`

思考是默认行为，因此 `/think` 也可省略。随后的通用 RL 阶段进一步强化这种模式和格式遵循。

这些 `/think` 和 `/no_think` 标志是一种"软"开关。但 `enable_thinking=False` 设置（在 False 情况下强制添加空的 `<think></think>`）则充当一种"硬"开关。

![](https://substackcdn.com/image/fetch/$s_!U8qX!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fd170e1f6-0838-487e-b3a6-7d501eb38962_1999x914.png)Qwen3 训练流程中的"思考模式融合"，用于实现推理模式的开关。

即分词器并不会在查询中添加 `/no_think`。它直接在助手响应的开头填入空 `<think></think>` 段。模型只看到最终的 token，然后直接继续生成答案。

总之，这种开关本质是 GPT-5.6 等模型中推理力度档位的简化版。

推理时，推理力度档位可以简单地通过系统提示词控制。（ChatGPT 界面大概只是将菜单选择映射到一个系统提示词。)但这对任意模型并不适用，需要对训练流程做某些修改。

### 5.2 可能的力度档位实现方式

虽 GPT 5.6 和 gpt-oss 训练细节都未公开，但通常推理力度标签会在后训练（post-training）期间包含在提示词中。

通常有两种实现方式：

- 将其作为 RLVR 流程的一部分，在使用不同系统提示词时施加不同的长度惩罚。例如，当"Reasoning effort: low"时使用较高的长度惩罚，当"Reasoning effort: high"时使用较低或不使用惩罚
- 在 RLVR 之后通过监督微调（SFT）微调模型，使其遵循不同的力度指令

如在核心 RLVR 阶段后的 SFT 期间，训练数据集中的提示词会与展现出期望推理量的目标响应配对。（目标响应可由人类编写、由另一个模型生成，或生成后再经过筛选。）

![](https://substackcdn.com/image/fetch/$s_!Ygd6!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Ff059bb1a-d06d-4a8b-81b3-5c78c5fa0551_1999x1169.png)力度条件化 RLVR 和 SFT 的示意图。（这是一种可能的实现，并非对 OpenAI 训练流程的确认描述。)

在这个 SFT 阶段，模型直接从训练示例中学习力度标签与目标推理长度之间的关联。而基于 RL 的实现则会将力度标签和预算感知奖励放在 RLVR 阶段中。两种方法也可以结合使用，怀疑 gpt-oss 和 GPT 5.6 都这么做的（注意 GPT 5.6 中的力度设置可能只是针对给定用户查询修改系统提示词)。

### 5.3 Inkling 案例研究

Inkling 技术报告给了一个虽小但较为具体的力度档位训练示例

![img](https://substackcdn.com/image/fetch/$s_!_ls7!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Fd6a88041-747e-494a-aacd-d4c6f7925b94_1999x987.png)Inkling 在 0.2 到 0.99 之间扫描连续力度值；较高力度通常产生更长的响应和更高的基准分数。

大规模 RL 期间，他们对每个样本做了两件事：

- 在系统消息中指定期望的力度档位
- 调整分配给每个生成 token 的成本

从概念上讲，奖励大概看起来像这样：

这里，*e* 是请求的力度档位，λ(e) 控制 token 惩罚。

- 低力度使用较大的每 token 成本，鼓励更短的推理轨迹。
- 高力度使用较小的每 token 成本，允许模型花费更多 token。

然后在推理时，Inkling 收到诸如 "Thinking effort level: 0.8" 这样的系统消息，并相应地调整其 token 使用量。Inkling 与 gpt-oss 和 GPT-5.6 等模型的区别在于，力度标签是 0 到 1 之间的连续数值，而非 low、medium、high 这样的有序标签。

这使得 Inkling 的力度档位条件化主要位于推理 RL 阶段，而不仅仅是在后续的 SFT 阶段。

不过，他们没有披露确切的奖励公式、token 成本系数，也没有说明力度条件化是否也包含在 SFT 中。

### 5.4 关于推理扩展与训练扩展的简短说明

与前面的"2.3 推理扩展简述"联系。

前面将扩展分为训练计算扩展和推理时扩展。GPT-5.6 界面提供一个很好的方式来说明二者的区别，如下图。

左侧，选择 Luna、Terra 或 Sol 会改变模型本身。粗略类比对应训练计算扩展。这些是分别训练好的模型。在固定的训练方案和数据集大小下，更大模型需更多训练计算。它通常也需更多的每生成 token 计算。

右侧，保持模型不变，只改变推理力度。这是推理时扩展。模型权重保持不变，但允许模型在答案上花费更少或更多的 token。

![](https://substackcdn.com/image/fetch/$s_!pHf9!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2Ffe3daa10-2327-4fa4-a71e-c318298e8b85_1999x1395.png)模型选择菜单和推理力度菜单对应两个不同的扩展轴。选择 Luna、Terra 或 Sol 会改变模型，而改变推理力度则调整固定模型的推理时计算。

从菜单中选不同模型在当下并不是训练扩展——训练已经完成。更好的理解是，模型菜单是在不同训练规模下产出的模型之间进行选择。

Artificial Analysis 结果展示两个轴在实践中如何相互作用。每条蓝色曲线对应一个模型——Luna、Terra 或 Sol。沿曲线移动（增加推理力度）是推理扩展。从一条模型曲线切换到另一条对应模型扩展，我在这里将其作为训练扩展的实际代理。

正如预期，两种方法都能提升基准分数，但也都会增加成本。更有趣的是，这些曲线存在重叠。例如，一个较小的模型在较高推理力度下，有时可以达到与较大模型在较低推理力度下相近的分数。

![](https://substackcdn.com/image/fetch/$s_!U4Fk!,w_1456,c_limit,f_auto,q_auto:good,fl_progressive:steep/https%3A%2F%2Fsubstack-post-media.s3.amazonaws.com%2Fpublic%2Fimages%2F5556b75b-3029-4134-8fad-3a243d7e36d7_1999x1514.png)GPT-5.6 模型家族在 Artificial Analysis Coding Agent Index 上的训练扩展与推理扩展。沿每条模型曲线移动对应增加推理力度。在 Luna、Terra 和 Sol 曲线之间切换对应选择不同的模型。

x 轴显示 API 成本而非原始计算量。API 成本是一个有用的实际指标，但它也取决于服务商的定价和生成 token 的数量。此外，这些曲线的确切形状是基准特定的。

因此，模型大小和推理力度构成了两个独立的旋钮。我们可用更大模型、增加推理力度，或两者结合。哪种组合最好取决于期望的准确率、成本和延迟。

## 6 总结

本文中的开放权重示例通过几种不同的机制实现推理力度。相似的标签背后可能是独立的专家模型、混合 SFT 数据、模式条件化奖励、硬 token 预算，或这些方法的组合。

很难说哪种方法最好。这些模型在基座检查点、训练数据、后训练计算量、基准测试和服务目标上各不相同。它们的报告也省略了进行受控比较所需的许多细节。（此外，可能不存在万能方案，一种在交互式助手上表现良好的方法可能并不适合长时间运行的编码智能体。）

终极目标当然是自动力度选择。我们之前在 GPT 5 的 Auto 模式中见过。这是一个棘手的问题，最终实现可能弊大于利，这也是它从界面中移除的原因。

不久将来，推理力度仍将是一个显式的模型输入，最常通过系统提示词传递。然而，围绕 LLM 的智能体包装器/框架（harness），或内部路由器，可能会越来越多地根据任务状态和可用资源自动推断合适的模式和预算（当然仍然允许用户覆盖）。

希望力度选择能变得更加自动化。类似 GPT 5 的 auto 模式，一个廉价的模型或路由器可以根据请求、工具状态以及剩余时间或 token 预算来选择模式，同时仍然允许用户覆盖。如果你想优化延迟或成本，或者追求最高性能，覆盖功能会很有用。
